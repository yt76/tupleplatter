# Tuple Platter

## 現状の問題

ソフトウェアエンジニア以外でもアプリケーションを簡単に作れるようになったように見えるが、「どうやって運用するのか？」が課題になっている。
この中で特にデータの置き方が大きな問題となっている。一般的に使われているのは下記2つであるが、どちらも実用的には厳しい。

- **SQLデータベース**：スキーマの管理が素人には無理。
- **スプレッドシート**：フリーフォーム過ぎて管理できそうにない。

上記の問題への対処として、Tuple Space という1980年代の技術を使うと良いのではないかと考えている。

## Tuple Spaceとは

Tuple Space（タプルスペース）は、1980年代に分散プログラミング言語「Linda」の一部として考案された、シンプルで柔軟なデータ共有の仕組みです。

データベースのテーブルやスプレッドシートのシートの代わりに、「スペース」と呼ばれる共有の場に「タプル（いくつかのキーと値の組を持つデータ）」を出し入れすることで、プログラム同士がデータをやり取りします。

主な特徴は以下の通りです。

- **事前のスキーマ定義が不要**：SQLのようにあらかじめ厳密なテーブル構造を決める必要がなく、使いたい形のデータをそのままスペースに置くことができます。
- **パターンマッチングによる検索・取得**：必要なデータを取り出すときは、「`type` が `"user"` で、`role` が `"admin"`」といった緩やかな条件（部分一致パターン）を指定して取得できます。
- **操作がシンプル**：基本は「置く（write/out）」「読む（read/rd）」「取り出して消す（take/in）」の3つだけで、学習コストが低く抑えられます。
- **アプリ間の連携が容易**：同じスペースにアクセスできるアプリ同士なら、お互いの存在を意識せずにデータの受け渡しや連携ができます。

SQLほど厳格すぎず、スプレッドシートほど無秩序でもない「ちょうどいい自由度」を持っているため、エージェントを使って素早く作ったアプリのデータ置き場として適しています。

## 開発・運用イメージ

アプリの開発者は、Tuple Platter にアクセスするプロトコル等が書かれたマニュアル（[MANUAL.md](./MANUAL.md)）をコーディングエージェントに読み込ませて開発を行う。
マニュアルにはデータのスキーマのドキュメント（`TUPLE_SCHEMA.md`）を出力するように記載するため、開発されたアプリは同じ Tuple Space にアクセスする他のアプリとスキーマを共有することができる。

- [MANUAL.md](./MANUAL.md)：コーディングエージェント向けのプロトコル仕様・実装ルール・スキーマ出力ガイドライン（ドラフト）
このドキュメントもTuple Space上に置くため、AIエージェントが直接アクセスしてデータを理解して操作することも可能である。

## 設計・仕様

- **シンプルな運用**：シングルファイル DB（SQLite）で分かりやすい deploy や backup ができる。
- **マルチスペース対応**：シングルバイナリで複数の DB をサーブする。
  - 1つのスペースは `hostname/path` に対応する。
  - `foo.db` を配置すると、`hostname/foo` 以下の URL で API アクセス可能になる。
  - この場合 `hostname/foo/api/v1/tuples` 以下にAPIアクセスが可能になり、 `hostname/foo` にアクセスすると人間がTuple Spaceを操作するためのUIがある。
  - `foo.db` と `bar/baz.db` を配置すると、`hostname/foo` と `hostname/bar/baz` でアクセス可能になる。
  - 何も指定しないでサーバーを起動すると、`default` という名前の Tuple Space を提供する(`default.db`が作成される)。
  - **パス名の予約語**：API エンドポイント（`/<space_path>/api/...`）と衝突するため、`api` はスペース名およびディレクトリ名として使用不可とする（例: `api.db`、`bar/api.db`、`api/baz.db` は不可）。
- **アクセスコントロール**：スペース単位で行う。
- **データ形式**：tuple は JSON Object（Key-Value）形式。トップレベルの値のうち、`value` が `dict`（ネストしたオブジェクト）または `array`（配列）の場合はパターンマッチング対象外とする。
